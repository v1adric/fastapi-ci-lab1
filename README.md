## Опис проєкту

**FastAPI Items Management Service** — вебсервіс, який надає REST API для створення, перегляду, оновлення та видалення елементів.

Дані передаються у форматі JSON. Для обробки HTTP-запитів використовується FastAPI, а для автоматизованого тестування — pytest.

Проєкт також демонструє використання Docker для пакування застосунку та Azure DevOps Pipelines для автоматизації процесів CI/CD із публікацією Docker-образу в Docker Hub.

## Технологічний стек

| Технологія | Призначення |
|---|---|
| Python 3.11+ | Мова програмування |
| FastAPI | Розроблення REST API |
| Uvicorn | ASGI-сервер для запуску застосунку |
| pytest | Автоматизоване тестування |
| Docker | Контейнеризація застосунку |
| Azure DevOps Pipelines | Автоматизація CI/CD |
| Docker Hub | Зберігання Docker-образів |

## Функціональні можливості

- Реалізація REST API для керування елементами.
- Підтримка CRUD-операцій.
- Обмін даними у форматі JSON.
- Обробка запитів із використанням HTTP-статусів.
- Автоматична документація API на основі OpenAPI.
- Інтерактивне тестування запитів через Swagger UI.
- Автоматизоване тестування за допомогою pytest.
- Контейнеризація застосунку за допомогою Docker.
- Автоматизація перевірок, збирання та публікації Docker-образу через CI/CD pipeline.

## API Endpoints

Базовий шлях API: `/api/items`

| HTTP-метод | Endpoint | Опис | Очікуваний статус |
|---|---|---|---|
| `GET` | `/api/items` | Отримання списку елементів | `200 OK` |
| `GET` | `/api/items/{id}` | Отримання елемента за ID | `200 OK`, `404 Not Found` |
| `POST` | `/api/items` | Створення нового елемента | `201 Created` |
| `PUT` | `/api/items/{id}` | Оновлення наявного елемента | `200 OK`, `404 Not Found` |
| `DELETE` | `/api/items/{id}` | Видалення елемента | `204 No Content`, `404 Not Found` |

Фактичні статус-коди залежать від реалізації відповідних обробників API.

## Вимоги

Для локального запуску необхідні:

- Python 3.11 або новіша версія.
- pip.
- Git.

Для контейнеризованого запуску додатково потрібен встановлений і запущений Docker.

## Локальний запуск

### 1. Клонування репозиторію

```bash
git clone https://github.com/v1adric/fastapi-ci-lab1.git
cd fastapi-ci-lab1
```

Замініть URL на адресу свого репозиторію. Якщо папка проєкту має іншу назву, перейдіть до відповідного каталогу.

### 2. Створення віртуального середовища

**Windows (PowerShell):**

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

**Windows (CMD):**

```cmd
python -m venv venv
venv\Scripts\activate.bat
```

**Linux / macOS:**

```bash
python3 -m venv venv
source venv/bin/activate
```

### 3. Встановлення залежностей

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Запуск автоматизованих тестів

```bash
pytest
```

Команда запускає тести, визначені в проєкті.

### 5. Запуск вебсервісу

```bash
uvicorn main:app --reload
```

Після успішного запуску сервіс буде доступний за адресою:

- API: http://localhost:8000
- Swagger UI: http://localhost:8000/docs
- OpenAPI schema: http://localhost:8000/openapi.json

## Запуск за допомогою Docker

Перед виконанням команд переконайтеся, що Docker запущено.

### 1. Збирання Docker-образу

У кореневому каталозі проєкту виконайте:

```bash
docker build -t fastapi-items-app .
```

### 2. Запуск контейнера

```bash
docker run -d -p 8000:8000 --name my-fastapi-app fastapi-items-app
```

### 3. Перевірка роботи

Відкрийте Swagger UI у браузері:

http://localhost:8000/docs

### 4. Керування контейнером

Перегляд запущених контейнерів:

```bash
docker ps
```

Перегляд журналів застосунку:

```bash
docker logs my-fastapi-app
```

Зупинка контейнера:

```bash
docker stop my-fastapi-app
```

Повторний запуск:

```bash
docker start my-fastapi-app
```

Видалення зупиненого контейнера:

```bash
docker rm my-fastapi-app
```

## CI/CD Pipeline

Проєкт інтегровано з **Azure DevOps Pipelines** для автоматизації процесу збирання та перевірки застосунку.

За налаштованої конфігурації pipeline запуск відбувається після виконання `git push` до гілки `main`.

### Етапи pipeline

1. **Build** — підготовка середовища та встановлення необхідних залежностей.
2. **Test** — запуск автоматизованих тестів за допомогою pytest.
3. **Docker Build** — збирання Docker-образу застосунку.
4. **Docker Push** — публікація Docker-образу в Docker Hub із тегом `latest`.

### Схема процесу

```text
Developer
    |
    v
Git Push (main)
    |
    v
Azure DevOps Pipeline
    |
    v
Install Dependencies
    |
    v
Run pytest
    |
    v
Build Docker Image
    |
    v
Push Image to Docker Hub
```

Публікація образу виконується за умови успішного проходження попередніх етапів, якщо це передбачено конфігурацією pipeline.

Для автентифікації в Docker Hub використовуються налаштовані в Azure DevOps облікові дані або Service Connection. Секрети та паролі не повинні зберігатися безпосередньо у вихідному коді репозиторію.

## Документація API

FastAPI автоматично генерує документацію API на основі визначених маршрутів і моделей даних.

Після запуску застосунку доступні такі ресурси:

| Ресурс | URL |
|---|---|
| Swagger UI | http://localhost:8000/docs |
| ReDoc | http://localhost:8000/redoc |
| OpenAPI JSON | http://localhost:8000/openapi.json |

Swagger UI дає змогу переглядати доступні ендпоінти, задавати параметри запитів і надсилати HTTP-запити безпосередньо з браузера.
